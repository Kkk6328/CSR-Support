# 表格設計改為所見即所得（設計畫面＝檢視畫面）

## 目標

目前「設計表格」中的單筆畫面設計使用獨立的 131×48 格線方塊，與使用者實際看到的檢視畫面不同，造成設計完成後仍需回到檢視畫面反覆確認。

本功能要改成真正的所見即所得（WYSIWYG）：**設計畫面直接使用與檢視畫面相同的版型、欄位外觀、尺寸與子表格呈現。設計時看到什麼，儲存後檢視就應該長什麼樣。**

## 核心原則

1. 單筆畫面設計不可再用抽象的 131×48 設計格線代表欄位。
2. 設計器的欄位容器、標題、內容區、子表格、對齊、字體、背景、尺寸，必須共用檢視畫面的 renderer / CSS；不要維護第二套視覺規則。
3. 設計模式只在實際檢視元件上疊加拖曳、縮放、設定、刪除等設計控制，不改變元件本身的實際版型。
4. 拖曳或縮放後要即時反映在畫面，不需要儲存後再回檢視確認。
5. 設計器仍保留欄位設定功能，但設定面板不要取代畫布；畫布永遠維持真實檢視外觀。

## 現況位置

主要實作在 `assets/ragic-table.js`：

- `renderLayoutDesigner()`：目前會建立 `.layout-grid`，並固定使用 `grid-template-columns: repeat(..., 131px)` / `grid-template-rows: repeat(..., 48px)`。
- `openDesigner()`：開啟「設計表格」。
- `openLayoutFieldSettings()`：欄位屬性設定。
- `attachLayoutDesignerEvents()`：拖曳與縮放。
- 檢視畫面已存在 `.ragic-view-field`、`.ragic-view-label`、`.ragic-view-value` 與子表格 renderer，應優先抽成共用 renderer，而不是在 designer 重做一套近似 HTML。

## 必做行為

### 單筆畫面設計

- 畫布外觀與單筆「檢視」畫面一致。
- 欄位標題與內容區的位置、padding、字級、背景、框線、對齊一致。
- 多行文字、下拉、日期、圖片、檔案、核取類欄位均以實際檢視元件樣式預覽。
- 子表格直接顯示真實表格外觀，包含：
  - 子欄位標題樣式
  - 內容樣式
  - 欄寬
  - 文字／背景顏色
  - 水平／垂直對齊
  - 每列顯示設定
- 沒有資料時可以用 designer sample value，但 sample value 必須放進實際檢視元件，不可另做假元件。

### 直接操作

- 拖曳欄位：在真實欄位卡片上拖曳。
- 調整寬高：在真實欄位邊界直接拖曳。
- 點欄位：開啟欄位設定。
- 設定變更：畫布立即更新。
- 刪除欄位：畫布立即移除。
- 新增欄位：新增後直接出現在所見即所得畫布，可立即拖曳。

## 列表設計

列表設計本身已使用預覽表格，可保留原功能；但應遵守相同原則：列表設計預覽與真正列表共用欄位樣式與對齊邏輯，避免預覽與實際列表不一致。

## 不要做

- 不要保留一套「設計專用尺寸」再於儲存時換算成檢視尺寸。
- 不要用固定 131px × 48px 方塊模擬檢視畫面。
- 不要在 designer 複製一份與檢視畫面相似但不同的 HTML/CSS。
- 不要要求使用者在「設計畫面」與「檢視畫面」之間來回切換確認效果。

## 驗收標準

1. 開啟「設計表格 → 單筆畫面設計」時，第一眼看到的版型與目前單筆檢視畫面一致。
2. 在設計畫面修改欄寬、高度、位置、文字格式或子表格格式後，畫面立即呈現最終效果。
3. 儲存後關閉 designer，進入同一筆資料的檢視畫面，排版與設計畫面一致；不可再出現明顯尺寸、字體、間距、對齊差異。
4. 子表格在設計畫面與檢視畫面的欄寬、標題樣式、內容樣式、水平／垂直對齊一致。
5. 既有 schema 相容，不因升級 WYSIWYG 造成原有欄位位置或資料遺失。
