# 遊戲排程背景同步需求

## 目標

即使沒有人開啟「📅排程表」頁面，正式系統仍須每 5 分鐘同步一次 Google 遊戲上線表。

## 現況

目前同步程式位於前端 `assets/schedule.js`：

- 開啟排程表時同步一次。
- 頁面保持開啟時，每 5 分鐘同步一次。
- 沒有人開啟頁面時，不會同步。

GitHub Pages 是純靜態前端，無法在所有人的瀏覽器都關閉後繼續執行工作。

## 正式後端需求

由正式後端新增定時工作，每 5 分鐘：

1. 讀取既有 Apps Script 遊戲排程 feed。
2. 驗證 `success` 與 `games` 回傳格式。
3. 依遊戲 ID 與預計上線日期建立或更新排程，必須可重複執行且不得產生重複資料。
4. 2026/07/01 起，先於上線前 14 天建立「向 AM 確認」。
5. 參照「備註 1」：含「首發」時，顯示「⭐ 首發平台 UAT」與「⭐ 首發平台 PROD」；含「獨家」時，顯示「🔒 獨家平台 UAT」與「🔒 獨家平台 PROD」。
6. 只有「AM 已確認」後，才建立行銷素材（前 8 天）、UAT／測試環境（前 7 天）及上線當日資料。
7. 將試算表欄位變更寫入既有變更記錄。
8. 同步失敗須留下可追查的錯誤記錄，下一輪繼續重試。
9. 前端的開頁同步與手動同步按鈕繼續保留作為補強。

## 資料與安全限制

- 使用既有 `schedule`、`scheduleLabels`、`scheduleGameChanges` 資料位置。
- 不在公開前端存放資料庫密碼、token、API 金鑰或內網位址。
- 不修改 `dev-server/` 並宣稱正式後端已完成；正式後端是獨立服務，須由後端維護端部署。

## 驗收條件

- 關閉所有排程表頁面至少 10 分鐘後，試算表變更仍會自動出現在正式系統。
- 同一批資料連續同步不會產生重複排程。
- `106009（性感炸彈：艾法）` 應先建立：
  `向 AM 確認｜🔒 獨家平台 PROD｜106009 (性感炸彈: 艾法)`
- 未勾選「AM 已確認」前，不得建立行銷素材、UAT 或上線當日資料。
- 勾選並儲存後，才建立後續三類排程。
